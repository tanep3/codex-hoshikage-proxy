# MCP承認 — Driveコメント一括操作の詳細設計

2026-09-17。対象google_drive.bulk_update_file_comments。取得済み定義のハッシュは全ツール台帳を正本とする。製品実装・実投稿前。

## 操作の意味と範囲

commentsは新規投稿、repliesは既存スレッドへの返信、resolutionsは解決済みへの変更。全体をwrite＋external_send、単発許可だけとする。解決は削除ではなく、返信本文の有無を区別する。配列間の処理順・全件成功の原子性は定義に保証がないため、画面で約束せず、途中失敗や結果不明から全件を自動再送しない。

対象はidまたはurlから得られる一つのDriveファイル。両方指定した場合は同一IDであることを検証し、相違・不正形式・対象なしはunknown_arguments。URLを実際に開いてリダイレクト先を対象にする処理は行わない。Google Workspaceの既知URL形式を評価済み規則で解析する。URL内の署名・個人情報等も公開範囲検査に含める。

comments/replies/resolutionsの省略・nullはその種類の操作なし、空配列は0件。合計1〜20件。未知のトップレベル／要素キーは受理しない。重複項目は同じ操作の複数指定として全件を表示し、Proxyが黙って重複除去しない。重複する返信・解決の適用順に依存する説明はしない。

## 新規投稿の全項目

| 項目 | 表示・検証 |
| --- | --- |
| content | コメント全文。必須string。MarkdownやメンションをDiscordで実行しない |
| quoted_text | 引用した対象の文。省略／nullは指定なし。実際のファイルとの一致確認済みとは表示しない |
| slide_number | 対象スライド番号。1以上の整数。番号から対象オブジェクトを推測しない |
| sheet_cell_range | 対象シート／セル範囲。原文を保持し、シート名を勝手に補完しない |
| anchor | 接続先へ渡す補助的な位置指定。後述の扱い |

少なくともquoted_textの非空指定、slide_number、sheet_cell_rangeの非空指定のいずれかで対象を利用者が区別できること。anchorだけで人間が位置を理解できるとはしない。複数の位置情報を指定した場合は全て表示する。既存文書の実データを根拠なく読み取った説明を作らない。

## anchorの扱い

[Google公式のコメント仕様](https://developers.google.com/workspace/drive/api/guides/manage-comments)では、anchorにはアプリ独自の形式があり、WorkspaceエディタはDrive APIで作ったコメントを文書内の位置に結び付けて表示する保証がない。したがって、任意のanchorを文書座標に翻訳しない。

非nullのanchorは重複キー・不正JSON・深さや文字数超過を検査する。受入れるJSONは補助データとして、固定ラベル「接続先へ渡す位置指定」と値全体を表示する。引用文・スライド・セル範囲による操作対象の説明を必ず併記する。これは未評価の内包命令をJSON表示だけで許可する例外ではない。anchorはこの固定APIのコメントに付属して保存するデータであり、別APIの選択や実行命令として解釈しない。独自キーを意味のわかる座標だと説明しない。

画面には「コメントが文書内の指定位置に表示されない場合があります。対象の引用・番号・範囲も確認してください」と添える。位置指定の値を隠して承認させず、秘密が含まれれば全体を依頼者だけの画面へ移す。添付リンクをProxyが開かない。

## 返信・解決とページ表示

repliesはcomment_idとcontent、resolutionsはcomment_idとreply_contentの全件を表示する。reply_contentの省略／nullは返信文なし、空文字は空文字を指定として区別。対象ファイルIDとスレッドIDの組を保持する。

表示は対象ファイル、新規投稿群、返信群、解決群の順。各群の件数と全項目を表示し、この表示順を上流の実行順とは呼ばない。非機密の内容は元会話、個人情報等は依頼者だけの画面、長文は既定の全ページ方式。どのページも省略せず、許可に全ページのtokenが必要。拒否は途中でも可能。
