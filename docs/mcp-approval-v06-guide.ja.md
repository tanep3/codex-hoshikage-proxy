# MCP承認0.6の使い方

ProxyはCodexへの実行と承認の仲介を担当します。Discordでの本人確認、メッセージ表示、ボタン操作はGatewayの担当です。OpenAI互換の`/v1`は引き続き利用できます。

## 操作を確認して許可する

対応クライアントでは、ツール名と実際の操作対象を確認できます。意味を評価していないツールも、取得できた引数を省略せずに表示します。「未評価」は「取得失敗」や「危険性なし」という意味ではありません。

- **今回だけ許可**：表示した1回の呼出しだけを許可します。
- **この依頼中、このツールを許可**：選んだポリシーで評価済みの通常操作に限り、同じ依頼の次の呼出しにも許可を適用します。通常の単発許可が自動的にこの許可へ変わることはありません。
- **拒否**：内容の取得に失敗していても拒否できます。

個人情報、連絡先、DM・メール、認証情報、実行コード、機密性を判断できない入力は、本人にだけ見える画面で確認します。「自分だけに表示して確認」は、その画面を他の参加者へ公開しないという意味です。長文も省略せず、必要なページを確認した後に許可できます。

停止、依頼の終了、追加発言（Steer）、設定の変更、再起動で、既存の依頼中許可は使えなくなります。別の会話・利用者・並列実行・次の依頼へ持ち越しません。`browser_evaluate`、任意コード実行、認証操作などは依頼中の自動許可対象ではありません。

## 管理者の設定

表示・単発承認には追加のON/OFF設定は不要です。クライアントは`GET /v2/codex/capabilities`の`mcp_approval_v06`を確認し、実行要求へ次を指定します。

```json
{
  "input": "依頼内容",
  "interaction_capabilities": ["mcp_form"],
  "approval_presentation": {
    "mode": "source_conversation",
    "profile": "source-conversation-v3"
  },
  "approval_context": {
    "principal_id": "利用者の識別子",
    "channel_id": "会話の識別子",
    "run_id": "今回の依頼の識別子"
  },
  "approval_policy": null
}
```

`approval_policy`の省略とnullは同じです。前の依頼のポリシーは引き継ぎません。表示を使うだけではNotionの禁止規則は有効になりません。

依頼中許可を提供する運用では、既存の`[v2] mcp_turn_approval_enabled = true`を使います。この設定だけで操作を自動許可することはありません。クライアントが今回のポリシーを指定し、利用者が依頼中許可を選んだ場合に適用します。

| ポリシー（versionは1） | 動作 |
| --- | --- |
| `evaluated-turn` | 評価済みの通常操作に依頼中許可を提供。未評価操作は完全な内容を確認した単発許可を維持 |
| `evaluated-turn-notion-guard` | 上記に加え、変更対象を保証できないNotion本文の部分置換を禁止 |

初期の意味評価対象は、照合済みの定義を持つ`browser_find`、`browser_navigate`、`browser_tabs`の一覧取得です。全MCPツールが依頼中許可の対象という意味ではありません。0.6では旧版のツール名allowlistで意味評価を代用しません。定義が変わったツールを名前だけで自動許可しません。

## 準備中・通信が切れたとき

受付後、Proxyが最大60秒で設定を準備します。Turn IDがまだなくても、Response IDまたは元の要求キーを指定して停止できます。設定送信の結果が不明な間は、AI未開始でも作業領域を占有する場合があります。停止成功や実行成功とは表示しません。元の依頼を新しいキーで自動再送しないでください。

再起動後も元の準備期限を維持します。設定結果が不明な場合、以前の上流プロセスが終了したことを照合してから占有を解除します。過去の要求を再実行することはありません。AI開始の結果が不明な場合は、既存のUNKNOWN復旧手順を使います。

## 更新・復旧

DBは起動時にschema 2から3へ移行します。会話・成果物・回答は保持します。新しい状態を旧バイナリへそのまま戻さないでください。停止中のバックアップと[復旧手順](v2-operations.ja.md)を使います。

APIの項目・上限・エラーは[接続契約0.6](mcp-approval-api-v06.ja.md)、実際の試験と未受入項目は[実装・受入記録](mcp-approval-v06-implementation.ja.md)を参照してください。
