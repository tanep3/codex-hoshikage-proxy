# MCP承認 — GitHubツリー作成の表示規則

2026-09-17。内部設計。規則IDはgithub_tree_elements。対象はcodex_apps/github.create_treeの隔離取得済み定義。実行・コード実装前。

## 入力と表示

repository_full_nameを対象リポジトリとして必ず表示する。tree_elementsは要素順に、path＝対象パス、mode＝ファイルの扱い、type＝参照の種類、sha＝既存内容の参照、content＝新しい内容全文を表示する。未知キーを落とさずunknown_argumentsへ分ける。値は無変更で実callへ対応付ける。

受入れるmode/typeの組：100644・100755・120000はblob、040000はtree、160000はcommit。表示はそれぞれ「通常ファイル／実行可能ファイル／シンボリックリンク／ディレクトリ／サブモジュール参照」。実行可能属性を付ける操作とコードを実行する操作を混同しない。

shaとcontentは排他。shaが明示nullなら、作成するツリーから対象を除く指定であり、shaの省略とは区別する。base_tree_shaがあればその基準ツリーを示し、なければ「列挙した要素だけで新しいツリーを作成」と表示する。この呼出しだけで現在のブランチを更新したとは説明しない。ここまでの意味は[GitHub公式のCreate a tree](https://docs.github.com/en/rest/git/trees#create-a-tree)と導入ツール定義の組合せで確認した。

同じpathの重複は適用順序を推測せずunknown_arguments。mode=040000/type=treeの非null SHA参照とその下位パスの併記は受け入れ、親ディレクトリ全体が子パス指定に基づく構造へ置き換わることを明示する。既存の子が維持されると約束せず、effectsへdeleteを含める。親がblob/commit、明示削除、または型不正なら下位パスとの併記はunknown_arguments。SHAを指定した既存内容は不変の参照として表示し、未取得の中身をモデルの説明から生成しない。

## 許可条件

新しいツリー情報・本文をGitHubへ送るためexternal_send、常に単発。削除要素を含めばdeleteも付け、「作成するツリーから除外」と説明する。既存grantの有無で変えない。公開可否は全実引数の内容検査で決める。非機密の本文は全文を公開できるが、秘密があれば呼出し全体を本人向けにする。

## 受入条件

- GTC01：通常ファイルの本文指定。パスと全文、外部送信・単発を表示。
- GTC02：既存SHA参照。内容を捏造せずSHAと種類を表示。
- GTC03：明示nullと省略を区別し、削除要素を検出。
- GTC04：sha/content併記、未知mode/type、不整合な組、未知キーを拒否。
- GTC05：シンボリックリンクと実行可能属性を通常ファイルと同じ説明にしない。
- GTC06：baseなしとありで基準を区別し、現在のブランチへの反映を断定しない。
- GTC07：親ディレクトリ・子要素の重複、重複パスで上書き対象を省略しない。
- GTC08：本文の秘密・長文・全要素の表示、途中欠落時の許可不可。

これらは設計上の合格条件。実行済みの試験結果ではない。具体入力と期待値は[GitHubツリー設計例](mcp-approval/github-tree-cases.json)。入力と提供元仕様の静的照合であり、GitHubへツリーを作成した結果ではない。


## 検証と表示の固定条件

全要素のpath/mode/typeと、shaまたはcontentのどちらか一方を要求する。mode/typeは上表の組だけ受け入れる。contentはblobに限る。未知キーはunknown_arguments。SHAは完全な40桁16進識別子として表示し、省略・null・空文字と混同しない。base_tree_shaの省略／nullは基準なし、空文字は不正。通常のUnicodeパスはそのまま扱い、絶対パス・空パス・空segment・`.`・`..`・制御文字を受け入れない。大小文字やUnicodeを正規化して別パスへ書き換えない。

表示順はリポジトリ→基準→「新しいツリーを作成。ブランチの更新は別操作」→要素の入力順。各要素の内容全文またはSHA、種類、削除指定を表示する。親子併記の作用は配列の順序に依存しないため、親の説明と子の説明に同じ対応番号を添える。JSONのキー順序に意味を与えない。

署名URL・連絡先・秘密がいずれかの値にあれば呼出し全体を本人向けへ移す。長文は表示上限規則に従う。受入形でもこの操作はexternal_sendで単発のみ。パス参照の内容は未取得なので「中身を確認済み」と表示しない。空配列は「要素指定0件」と明示し、baseの有無を省略しない。基準なしの場合に将来のcommitで既存ファイルが維持されると説明しない。
