# MCP承認の実利用で判明した導線・確認削減の是正

2026-09-16。常駐接続試験の利用者報告を受けた修正要求。既存0.3の安全条件を緩和するものではない。実装前に双方の文書へ反映する。

## 確認した事実

- Gateway `src/mcp_ui.rs` は公開カードに「操作内容を確認」「拒否」「この作業の許可」を表示する。
- 「この作業の許可」のcustom_idは `mt:grants:<request>`。`src/mcp_grants.rs` の一覧・取消画面を開くものであり、許可を与える操作ではない。
- 単発許可・ターン許可は本人限定の詳細画面にある。公開カードで説明する「今回だけ許可」は、その公開カード自体にはない。
- `browser_evaluate` はページ内のJavaScript実行であり、0.3ではターン許可対象外。Proxy常駐の対象は `playwright.browser_find` のみ。
- Proxyの5回→1回という実証は、2ツールに限定したカタログでbrowser_findを明示指定したもの。通常公開カタログの自由なモデル選択における改善は未確認だった。利用者の通常依頼ではevaluateが反復し、確認削減を達成できていない。
- 利用者報告の「この作業の許可を押したら操作内容を確認しろ」はボタンの意味の取り違えを生む導線として問題。現行コードで同ボタンは一覧へ遷移するため、実際のクリックイベントとの一致は追加照合が必要。古い単発ボタンの操作を拒否する文言と混同して断定しない。

## Gatewayの修正要求

1. 一覧入口を「許可一覧・取消」に改名する。公開カードと集約カードの双方に適用。押下によって許可が付いたと受け取れる表現をなくす。
2. 公開カードの主操作は「操作を確認して許可」、副操作は「拒否」とする。本文で「確認画面で、この1回だけ許可するか選べます」と説明する。対象外ツールには包括許可できると示唆しない。
3. 本人限定画面に操作内容と「今回だけ許可」「拒否」を置く。Proxyが対象と判定した場合だけ「このターン中、このツールを許可」を追加する。ターンの意味と引数変更も許可することを同画面で説明する。
4. 対象外の場合は理由を平易に表示する。evaluateでは「ページ内でプログラムを実行するため、この呼出しは個別の確認が必要です」とし、許可一覧へ誘導して解決できるように見せない。
5. 古いボタン・詳細未確認からの許可は拒否を維持する。ただしエラー文だけで行き止まりにせず、有効な操作詳細画面を開ける入口を返す。表示内容とfingerprint/revisionの照合を省略しない。
6. 利用者・管理者マニュアルの画面構成を実際の二段階導線へ合わせる。「公開カードに拒否／単発／ターン許可の3ボタンがある」と案内しない。

受入：本人として公開カード→詳細→単発許可／対象ツールのターン許可、一覧表示のみでは返信されないこと、対象外で包括許可の選択肢がないこと、旧カードの押下後に適切な画面へ戻れること、拒否時に誤許可しないことを実Discordで確認する。

## 最終合意とProxy側の確定範囲

その後、利用者から「evaluateはやっぱ危険だからいまのままでいい」「evaluateを使わずに検索してって言えばいい」と指示を受領した。browser_evaluateは個別確認を維持し、対象化やブラウザー経路の追加設計は今回の改訂に含めない。Discordでコード評価を使わず専用検索・読取りツールを使うよう依頼する運用とする。指示だけでモデルの選択を強制する仕組みではなく、evaluateが選ばれた場合は個別確認へ戻る。

Proxy側は契約0.3と常駐設定（機能ON、ターン限定許可対象playwright.browser_find）で確定。通常依頼での確認削減を全面的に検証済みとは扱わない。Gateway側のボタン名称・導線の是正と実Discordでの結合受入は残る。

## 後続改訂の扱い

利用者・Gatewayから、通常の承認を依頼元会話の最初のカードで完結させる新しい要求を受領した。[0.4接続レビュー案](mcp-inline-approval-api.ja.md)を次期導線の正本候補とする。上記の二段階導線は0.3の是正案の履歴であり、新UIの到達目標ではない。新契約が合意・実装されるまで現行の秘密保持と本人認可を緩和しない。
