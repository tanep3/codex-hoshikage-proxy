# OpenWebUI・Gatewayのクライアント受入確認

2026-09-13更新。OpenWebUI 0.11.3 / PIPE 0.6.0（2026-09-11反映記録）。Gatewayは拡張API v2を使用する。
同一OpenWebUIユーザーの別チャット間で文脈を共有することは、利用者が指定した仕様であり、不具合と扱わない。

## OpenWebUIで試す操作

同時に複数項目を試さず、操作時刻・選択モデル・エラー本文を控える。

| 項目 | 操作例 | 確認すること |
| --- | --- | --- |
| 通常応答 | 「テスト成功、とだけ答えて」 | 一度だけ回答し、生成中表示が終了する |
| 文脈共有 | チャットAで「合言葉は青い灯台」。同じユーザー・モデルのチャットBで「合言葉は？」 | 指定どおり文脈を共有する。別ユーザーとは共有しない |
| 承認・許可 | 以前承認が出た無害な操作を依頼し、対象と内容を確認して許可 | ダイアログが出て、許可後に処理が進み、回答が完了する |
| 承認・拒否 | 同様の依頼で拒否 | 拒否した操作を実行せず、待ち続けない。拒否したことを確認できる |
| 明示停止 | 作業ディレクトリ内で `sleep 30` の後に回答する依頼を出し、生成停止を押す | 対象の実行が終了し、次の普通の質問へ回答できる |
| モデル変更 | 会話内で固有の情報を伝え、同じProviderの別モデルへ変更して質問 | 選んだモデルに切り替わり、表示中の会話情報を参照できる |
| 承認中の画面再読込 | 承認画面が出たところで再読込し、状態確認後に次の質問 | 旧ダイアログの操作が別の実行を承認せず、永続的に実行枠を占有しない |

PIPEはまだv1の生成・制御APIを使用する。Gatewayのようなv2成果物一覧・保存回答の再配信UIは未実装。
PIPEのResponse対応表はメモリ上にあるため、PIPE再読み込み・OpenWebUI再起動を跨ぐ共有文脈の永続保持を保証しない。
画面再読込がどのタイミングでバックエンドの生成を中断するかは、実画面で確認する。

## Gateway側で確認する操作

- 通常投稿の受付・回答。同じ会話で前の情報を参照できる。
- 受付直後および実行中の `/stop`。停止受付と停止完了を区別し、`/resume`で元の停止依頼を再実行しない。
- 専用ワークに短いテキストを作り、登録ツールで公開。`/get`で同じ内容を取得する。
- 原本を更新しても、既存artifact IDから取得する内容が変わらない。
- 保存回答の配信前にGatewayのDBを再読込し、同じ回答を取得する。AI実行を追加しない。
- 結果不明の配信を自動再送しない。`/retry`の確認操作で同じ保存版を再送する。

実Discordの投稿テストは、投稿してよいチャンネルを指定してから実施する。
常駐サービスを止める復旧試験は、既存の処理を確認してから行う。
