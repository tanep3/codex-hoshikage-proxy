# Discordで使うMCPの許可：利用者・管理者ガイド

> API 0.6対応クライアントについては[新しいガイド](mcp-approval-v06-guide.ja.md)を参照してください。本書は旧profileの設定・操作説明を保持しています。

現行の接続契約0.3とProxy実装に対応する。2026-09-16 20:31 JST現在、Gateway・Proxyとも常駐反映済み。利用者の明示指示により接続試験用に本機能をONにし、対象はplaywright.browser_findに限定している。実Discordとの結合受入は未完了。以下は対応版の導入手順であり、本番受入済みという意味ではない。

## Discordを使う方へ

設定ファイルを編集する必要はありません。公開カードの「操作内容を確認」から本人限定画面を開き、そこで許可を選びます。現行の公開カードの「この作業の許可」は許可一覧・取消への入口で、許可を与えるボタンではありません。この紛らわしい名称は[是正要求](gateway-mcp-approval-ux-correction.ja.md)の対象です。画面の正確なボタン名はGatewayの利用者マニュアルを参照してください。

| 選択 | 意味 |
| --- | --- |
| 拒否 | 表示された呼出しを許可しません。依頼全体の停止とは区別します |
| 今回だけ許可 | 表示された1回だけを許可します |
| このターン中、このツールを許可 | 表示された範囲で、同じツールの後続呼出しを確認なしで通します |

「このターン」は現在処理している1回の依頼です。同じチャット全体への許可ではありません。追加発言（Steerを含む）、停止、ターン終了、期限切れ、設定世代変更などで失効します。有効期間は最大10分です。別利用者・別チャンネル・並列の別Runへ引き継ぎません。

ターン限定許可は、最初に表示した引数だけに限定されません。同じツールが別の引数で呼ばれることも許可します。アクセス先サイトを限定する機能ではありません。操作範囲に納得できない場合は「今回だけ許可」を選んでください。

すべての呼出しで3つの選択肢が使えるわけではありません。管理者が対象にしていないツール、危険なコード実行、秘匿した引数がある呼出し、対応付けを確認できない要求などではターン限定許可を提供しません。browser_evaluate／browser_run_code_unsafeは毎回個別確認です。

許可一覧・取消はGatewayの `/mcp` を使います。取消は今後の適用を止めますが、既に送信した呼出しを取り消す保証はありません。依頼自体を止めたいときは `/stop` を使い、実際の停止結果を確認してください。

## サーバー管理者へ：現行版で必要な設定

**現行版はバイナリ更新だけでは本機能が有効になりません。** Proxyの設定には次の2項目があります。Discord利用者が操作する設定ではありません。Gateway側に同じスイッチを追加する必要もありません。

| Proxyの `[v2]` 設定 | 初期値 | 役割 |
| --- | --- | --- |
| `mcp_turn_approval_enabled` | `false` | 操作詳細APIとターン限定許可の機能を提供する。trueでも自動で許可を作成しない |
| `mcp_turn_grant_tools` | `{}` | 管理者が評価したMCPサーバー名とツール名の組合せ。空ならターン限定許可の対象なし |

スイッチがtrueでも、利用者が明示的にターン限定許可を選ぶまでは、後続呼出しを自動許可しません。危険ツールなどの除外判定は対象一覧より優先します。名前一致やMCPの自己申告だけで安全と認定せず、接続先・実装・引数で可能な操作を確認してください。

### 導入手順

1. [検証記録](mcp-turn-approval-validation.ja.md)の確認済み範囲と未完了項目を確認し、まず隔離環境で対向Gatewayとの受入を行います。
2. Proxyサービスが実際に読むconfig.tomlを確認します。このサーバーの配置は[常駐運用記録](server-operations.md)に記載しています。Codex自身の `~/.codex/config.toml` やGatewayの設定ファイルへ次の項目を書いても、Proxyの設定にはなりません。
3. 対象ツールを評価し、既存の `[v2]` 内へ設定します。同じ `[v2]` を重複追加しないでください。次は隔離試験で評価した組合せの例であり、任意の同名サーバーを安全と保証するものではありません。

```toml
[v2]
mcp_turn_approval_enabled = true
mcp_turn_grant_tools = { playwright = ["browser_find"] }
```

4. 常駐への導入は受入・配備判断後に行います。新規受付を止め、活動中の依頼と結果不明の処理を照合し、安全に切替可能な状態にして対応版と設定を配置します。設定は起動時に読み込むためProxyの再起動が必要です。上流承認形式もプロセス全体で変わるので、既存クライアントへの影響を確認してください。チャットの再作成は不要です。
5. Bearer認証付き `GET /v2/codex/capabilities` で下記を確認します。Gatewayは両項目を独立判定します。readyだけで確認を終えないでください。

```json
{
  "mcp_operation_details": { "enabled": true, "profile": "native-item-id-v1" },
  "mcp_turn_approval": { "enabled": true, "profile": "native-item-id-v1" }
}
```

上記は応答の抜粋です。capabilityがtrueでも、各呼出しがターン限定許可の対象とは限りません。本人限定画面の操作内容、単発許可、対象ツールのターン限定許可、一覧・取消、次発言での失効まで確認します。具体的な照合条件は[API契約](mcp-turn-approval-api.ja.md)を参照してください。

### 選択肢が出ない場合

| 症状 | 管理者の確認先 |
| --- | --- |
| capabilityの項目がない／profileが非対応 | 実行中のProxy版とGateway対応版 |
| enabledがfalse | 実際に読まれたProxy設定、変更後の再起動 |
| enabledはtrueだがターン許可を選べない | 対象一覧のサーバー名・ツール名、操作詳細の `turn_grant_eligible` と `ineligible_reason` |
| 許可後も次の発言で確認される | 正常動作。前の発言への許可を引き継がない |
| 操作詳細が取得できない | 期限、設定世代、接続状態、Gatewayの本人認可。推測した内容で許可しない |

常駐で機能を無効化する場合も、安全な切替手順を踏んで `mcp_turn_approval_enabled = false` にし、再起動後のcapabilityを確認します。これは現在の呼出しを即座に止めるスイッチではありません。即時の依頼停止は停止API／ `/stop` で行います。無効化すると操作詳細APIも無効になる点に注意してください。

## Gatewayマニュアルへの反映事項

Gateway側では、次の2か所を分けて案内してください。Proxyの設定仕様の正本はこの文書とし、導入説明からリンクします。Gatewayに機能ONを推測させたり、利用者へProxy設定編集を求めたりしません。

- **利用者向け**：上記3選択の意味、対象外ではターン許可を提供しないこと、引数の変化を含む許可範囲、次発言での失効、 `/mcp` と `/stop` の違い。
- **管理者向け**：対応Proxy版に加えて現行の2設定が必要なこと、設定例、再起動、両capabilityの確認、本機能が使えない場合の確認先。本書「サーバー管理者へ」へのリンクを付ける。

説明文の例：

> MCPのターン限定許可を利用するには、Proxy管理者による対応版の導入と対象ツールの設定が必要です。Discord利用者は設定変更不要です。本人限定画面で「今回だけ」または「このターン中」を選びます。ツールや呼出しによってはターン限定許可を選べません。導入・設定確認はProxyの「Discordで使うMCPの許可：利用者・管理者ガイド」を参照してください。

独立した有効化スイッチを整理する案は検討段階です。現行設定・既定値・契約を変更した扱いにはしません。将来変更する場合は契約と両マニュアルの移行案内を先に更新します。

## 次期UIの改訂案（未提供）

[0.4接続レビュー案](mcp-inline-approval-api.ja.md)では、公開可能な操作説明と許可ボタンを依頼元会話の最初のカードへまとめ、許可一覧・取消を /mcp に分離する。公開情報だけで判断できない場合だけ、理由を示して本人限定補足へ進む。現行常駐の操作手順は上記0.3のまま。利用者は検索語・アクセス先URLなどの操作対象を元会話へ表示する方針を選択済み。認証情報・秘密入力・任意コードは本人限定補足へ分ける。通常の検索・URL移動は最初のカードで許可できる次期契約とし、接続レビュー・実装・結合受入後に利用手順を置換する。未識別の秘密を自由文から完全に検出する機能ではなく、公開対象は会話の閲覧者にも見える。
